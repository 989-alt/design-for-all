# PRD — 모두의 교실 디자인 스튜디오 (design-for-all)

작성 2026-10-10 · Fable 5.1 · 하네스 01 기획 4~6단계 산출물. 교과 근거는 `docs/design-for-all/교과분석.md` 의 지도 내용 번호 ①~㉓.

## 1. 누가, 언제, 무엇을 대신하나

| 항목 | 결정 (승인 2026-10-10) |
| --- | --- |
| 대상 | 초등 5학년, 미술 10단원 「모두를 위해」 |
| 차시 | **4~6차시 「제품 디자인 전람회 열기」의 디자인 활동(문제점 찾기→조사→설계→제작→돌아보기)을 대체**. 실물 모형 제작·전람회 실행⑲은 교사가 별도 진행 |

| 게임 중심 | **유니버설 디자인(모두를 위한 디자인) 전면**, 교과서 틀(요소 6·과정 5단계) 유지. '유니버설 디자인' 용어는 지도서 배경지식(⑦)에서 가져온다 |

## 2. 게임 한 줄

학생은 「학교 디자인 스튜디오」 신입 디자이너. 교실 사용자 6명의 불편을 모아 제품 하나(책상·사물함·교실 문)를 부품으로 다시 설계하고, 6명이 써 보게 해 **한 가지 해결책이 여럿을 편하게 하는지** 확인하며 고친다.

## 4. 핵심 규칙

### 4.1 사용자 NPC 6명과 불편 카드 17장

이름은 가상. 실존 인물·제품명 없음. 카드는 `누가 · 어디서 · 무엇이` 세 칸.

| NPC | 특성 | 책상 | 사물함 | 문 |
| --- | --- | --- | --- | --- |
| N1 서윤 | 휠체어를 탄다 | C01 책상 밑에 휠체어가 안 들어가 | C02 위 칸은 손이 안 닿아 | C03 문이 무거워 혼자 열기 힘들어 |
| N2 도현 | 키가 크다 | C04 책상이 낮아 무릎이 부딪혀 | C05 아래 칸은 허리를 많이 숙여야 해 | — |
| N3 하준 | 팔에 깁스 | C06 책상을 옮기기 힘들어 | C08 자물쇠 열기가 힘들어 | C07 둥근 손잡이를 돌리기 힘들어 |
| N4 지안 | 눈이 잘 안 보인다 | C09 책상 모서리가 어디인지 잘 안 보여 | C10 번호가 작아 내 칸을 못 찾아 | C11 문이 벽이랑 색이 같아 잘 안 보여 |
| N5 하은 | 도우미 활동 온 1학년 | C14 책상이 높아 발이 안 닿아 | C13 위 칸에 손이 안 닿아 | C12 문이 무거워서 못 열어 |
| N6 할머니 | 방문객, 손목·무릎이 아프다 | C17 가방·지팡이 둘 곳이 없어 | — | C15 손잡이 돌리면 손목이 아파 / C16 글씨가 작아 교실 이름을 못 읽어 |

의도된 구조: C02=C13, C03=C12, C07=C15 는 **같은 해결책이 둘을 만족**시킨다(저상 버스 논리 ⑦). C04↔C14 는 **부딪히는 요구**라 "높이 조절"만 둘 다 만족시킨다.

### 4.2 제품 3 × 슬롯 5 × 부품 4 = 60 (효과표 초안, 확정은 T02 콘텐츠)

표기: `[C..]` 푸는 카드(full), `(C..)` 부분 해결, `✗C..` 그 카드를 더 나쁘게, `★` 첨단, `♻` 환경.

> 2026-10-11 §4.2 수정(03 T02 리뷰에서 01 로 되돌아옴): 교실 문 F2 를 full→partial, A3 의 C07·C15 를 full→partial. 이유 — 무작위 플레이 기대 만족이 문 3.09/5 로 §4.7 상한(n/2=2.5)을 넘었다(책상 2.66/6·사물함 1.75/5 는 통과). 수정 후 기대값 약 2.2/5. 가벼운 경첩문은 여전히 당겨 열어야 하고 막대 손잡이도 손으로 잡아야 하므로 '부분'이 교과 내용(⑦ 저상 버스 = 계단 자체를 없앰)과도 맞는다. 전원 만족 조합은 F3/F4 + A2/A4 + B2/B3 + K2 로 유지.

**책상**
- 형태 F: F1 네모 모서리(기본) / F2 모서리 둥글고 고대비 테두리 [C09] / F3 ㄷ자 벽면 책상 / F4 책상+의자 일체형 ✗C01
- 기능 A 높이: A1 고정 보통 / A2 고정 높게 [C04] ✗C14 / A3 수동 높이 조절 레버 [C01 C04 C14] / A4 전동 높이 조절 ★ [C01 C04 C14]
- 기능 B 이동·수납: B1 고정 다리 / B2 잠금 바퀴 [C06] / B3 옆 가방·지팡이 걸이 [C17] / B4 아래 수납 선반 ✗C01
- 소재 M: M1 새 플라스틱 / M2 재활용 플라스틱 ♻ / M3 가벼운 알루미늄 [C06] (♻ 절반) / M4 재생 나무 ♻

**사물함**
- 형태 F: F1 위아래 2단 똑같이 / F2 허리 높이 칸이 많은 섞인 배치 [C02 C05 C13] / F3 회전식 원형 (C02 C13) / F4 긴 세로 1칸 (C05)

### 4.3 NPC 반응 판정

제품 하나에 대해 **그 제품의 카드를 가진 NPC 만** 테스트에 나온다(책상 6명, 사물함 5명, 문 5명). 각 NPC 의 카드 집합을 본다. 전부 full → **만족**. 일부 full 또는 partial → **부분**. 없음 또는 ✗ 있음 → **불만**(✗ 가 있으면 이유에 그 부품을 지목). 반응 한 줄은 카드별 고정 문장 + 부품명 치환.

### 4.4 점수 (요소 6, 0~100)

| 요소 | 식 |
| --- | --- |
| 누구나 편리(주축) | 만족 NPC / 해당 NPC 수(책상 6·사물함 5·문 5) |
| 목적에 맞음 | 선택 부품 중 **연결이 맞는** 부품 / 5. 맞음 = 연결한 카드가 그 부품의 효과표에 있음 |
| 기능성 | 해당 제품의 카드 중 full 해결 / 전체 |
| 아름다움 | 조화표 (형태,색,소재) 조합 0·50·100 (T02 가 정의, 각 제품 64조합 전부 값 있음) |
| 환경 | ♻ 100, ♻절반 50, 그 외 0 |
| 최신성 (참고 축) | 연결된 ★ 부품 있으면 100, ★ 있는데 연결 없거나 틀리면 0 + M3 피드백, ★ 없으면 "해당 없음". **판정식에 안 들어간다** |

### 4.5 수정 루프

- 1차 테스트 후 "수정" 필수. 부품 0개 변경이면 재테스트 버튼 비활성.
- 바꾼 이유 = NPC 반응 중 하나 지목(로그 `revise.reason`).
- 2회 수정 뒤 최종. 수정 없이 끝내는 길 없음(M4).

### 4.6 등급

판정식 S1~S6 통과 수: 6 → 「모두의 디자이너」, 4~5 → 「배려 디자이너」, ≤3 → 「견습 디자이너」. 등급은 결과 화면에만. "실패" 문구 없음.

### 4.7 우회 불가 조건

부품을 무작위로 끼우고 연결도 무작위인 플레이 10,000판에서 **S1~S6 동시 통과율 < 1%**, 만족 NPC 기댓값 ≤ 해당 NPC 수의 절반. 단위 테스트로 고정(T03). 넘으면 효과표를 고친다.

## 7. 성공 판정식 (실행 가능)

결과 JSON `result.json` 에 대해 `scripts/check-result.mjs` 가 계산한다.

| ID | 판정식 | 근거 |
| --- | --- | --- |
| S1 | 최종 라운드 불만·부분 NPC ≤ 1 (해당 NPC 수 n 중 만족 ≥ n−1) | ⑭⑯ 주축, ㉑ 표현 |
| S2 | 최종 라운드 연결 맞는 부품 ≥ 4/5 | ⑯, M3 |
| S3 | `revise.count ≥ 1` ∧ 모든 수정에 `reason` 있음 | ⑰, M4 |
| S4 | 사례 태깅 7장 중 첫 시도 정답 ≥ 5 ∧ 저상 버스 카드 정답 | ④⑥⑦ |
| S5 | 돌아보기 `reflect.good`·`reflect.fix` 각 요소 태그 ≥1 ∧ 샘플 칭찬 2개 모두 요소 이름 포함 | ⑳㉑ |
| S6 | 불편 카드 수집이 3명 이상 NPC 에서 ∧ 선택 제품의 카드 ≥ 3장 포함 | ⑭ |
| S7 | 우회 검사: 무작위 10,000판 S1~S6 동시 통과 < 1% (단위 테스트) | §4.7 |
| S8 | 40분: seeded e2e(`?e2e=1` 자동 조작)에서 화면 전환 ≤ 20, 대화 ≤ 12, 애니메이션 누적 ≤ 2분. 실측은 사람 검증 체크리스트(학생 3명 평균 30~40분) | §3 |

## 9. 데이터 모델 초안

저장소: 브라우저 `localStorage` 키 `dfa.save.v1`, 상태가 바뀔 때마다 저장(중단 복구용). 완주 저장본은 결과 화면으로 복원, 「처음으로」에서 삭제. 학생 개인정보: **받지 않는다**(이름·번호 입력 없음). PNG 저장은 `canvas.toBlob` 다운로드.

```ts
type Stage = 'title'|'cases'|'classroom'|'pick'|'research'|'design'|'test'|'revise'|'reflect'|'result'
interface GameState {
  v: 1; seed: number; stage: Stage; startedAt: number
  tags: { caseId: string; tried: string[]; correct: boolean }[]        // 사례 태깅
  collected: string[]                                                   // 불편 카드 id
  product: 'desk'|'locker'|'door'|null
  research: { refId: string; cardId: string }[]                         // 참고 카드 → 불편 카드
  rounds: { slots: Record<SlotId, PartId>; links: Record<SlotId, string|null>
            reactions: Record<NpcId,'happy'|'partial'|'unhappy'>; satisfied: number
            reason?: NpcId }[]                                          // rounds[0] 1차, 이후 수정
  reflect: { good: ElementId[]; fix: ElementId[]; praise: { sampleId: string; element: ElementId; line: string }[] }
  feedback: string[]                                                    // 노출된 피드백 카드 id (bus, tech...)
  log: { t: number; e: string; d?: unknown }[]
}
```

결과 JSON = `GameState` + 점수 6 + S1~S6 판정. `scripts/check-result.mjs` 가 읽는다.

## 11. 스택 (근거 한 줄씩)

| 층 | 선택 | 근거 |
| --- | --- | --- |
| 프론트 | **Vite + TypeScript + Preact (DOM)** | 카드·슬롯·대화 UI 라 게임 엔진 불필요. 설치 없이 브라우저. world-trade 와 도구 통일(Phaser 만 뺌) |

| 접근성 | **이 게임 자체가 UD** — 전 조작 키보드 가능, 포커스 표시, 대비 4.5:1 이상 토큰, 글자 크기 2단, 색만으로 정보 전달 금지, 모든 NPC·부품에 라벨, `prefers-reduced-motion` 존중 | 주제와 제품이 어긋나면 안 된다 |

| 상태·저장 | 단일 리듀서 + 시드 난수(자체) + `localStorage` | 백엔드 없음, 결정적 e2e |
