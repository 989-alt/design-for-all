# Product

<!-- impeccable:product-schema 1 -->

하네스 규칙에 따라 `docs/design-for-all/` 에 둔다. 사실은 전부 `PRD.md`(사용자 승인 2026-10-10)와 `교과분석.md` 에서 옮겼다. impeccable init 의 인터뷰 대신 PRD 승인 이력이 출처다. 인터뷰로 새로 물은 것은 없다.

## Platform

web

## Stack

delegated(PRD §11, 사용자 승인): Vite + TypeScript + Preact(DOM). Phaser 없음 — 카드·슬롯·대화 UI 라 게임 엔진 불필요. 제품 미리보기는 절대 배치 `<img>` 레이어 합성, PNG 저장만 canvas. 정적 빌드(`base:'./'`), GitHub Pages 또는 index.html 직접 열기. 백엔드·네트워크 호출 0.

## Users

초등학교 5학년(만 10~11세). 미술 10단원 「모두를 위해」 4~6차시 「제품 디자인 전람회 열기」의 디자인 활동(문제점 찾기→조사→설계→제작→돌아보기)을 이 게임이 대체한다. 1인 1기기(태블릿·크롬북 가로), 혼자, 40분 한 판 완결. 교사는 결과를 보지 않고 교사용 화면도 없다(정적 교사 안내 1쪽만).

## Product Purpose

성취기준 [6미01-03]·[6미02-01](평가 기준)·[6미02-04]·[6미03-03]·[6미03-04] 아래, 교과서의 제품 디자인 요소 6(목적·최신성·기능성·아름다움·누구나 편리·환경)과 과정 5단계를 **유니버설 디자인(모두를 위한 디자인) 전면**으로 익힌다. 학생은 「학교 디자인 스튜디오」 신입 디자이너로서 교실 사용자 6명의 불편을 모아 제품 하나(책상·사물함·교실 문)를 부품으로 다시 설계하고, 6명이 써 보게 해 **한 가지 해결책이 여럿을 편하게 하는지** 확인하며 고친다. 성공은 판정식 S1~S8(PRD §7)로 잰다: 만족 ≥ n−1, 연결 정합, 수정 1회 이상, 돌아보기 태그, 우회 검사(무작위 10,000판 통과 <1%).

## Positioning

'예쁜 제품 그리기' 앱이 아니라 **사용자 반응으로 디자인을 고치는 게임**이다. 같은 해결책이 둘을 만족시키는 카드 구조(C02=C13, C03=C12, C07=C15)와 부딪히는 요구(C04↔C14, 높이 조절만 둘 다 만족)가 저상 버스 논리(지도서 배경지식 ⑦)를 몸으로 겪게 한다. 수정 없이 끝내는 길이 없다(M4). 등급에 "실패" 문구가 없다.

## Operating Context

- 교실, 태블릿·크롬북 가로 1280×800 기준. 마우스·터치·키보드. 히트박스 48px 이상.
- 라운드 0~8(의뢰·사례 7장 태깅·문제점 찾기·조사·설계·테스트·수정·돌아보기·결과), 40분. seeded e2e 로 화면 전환·대화 수 상한.
- 저장: `localStorage` 키 1개 `dfa.save.v1`, 상태 바뀔 때마다. 완주본은 결과 화면 복원, 「처음으로」에서 삭제. 결과 PNG 는 `canvas.toBlob` 다운로드.
- 소리: BGM 2(스튜디오 루프·결과), 효과음 8. 전부 끌 수 있고 소리에만 의존하는 정보 없음.

## Capabilities and Constraints

- NPC 6(서윤 휠체어·도현 키 큼·하준 깁스·지안 저시력·하은 1학년·할머니 손목·무릎), 불편 카드 17(누가·어디서·무엇이). 제품 3 × 슬롯 5(형태·기능A·기능B·소재·색) × 부품 4 = 60, 효과표는 T02 콘텐츠 계약이 확정.
- 테스트엔 그 제품의 카드를 가진 NPC 만(책상 6·사물함 5·문 5). 반응 만족·부분·불만 + 한 줄 이유. 점수 요소 6(0~100), 최신성은 참고 축.
- 수정 1회 이상 강제, 최대 2회. 바꾼 이유는 NPC 반응 지목.
- 용어: '유니버설 디자인'은 지도서 표현 "모두를 위한 디자인"과 함께 쓴다. 실존 제품명·회사명·실존 인물 없음. 이름은 전부 가상.
- 개인정보 0(이름·번호 입력 없음), 계정·랭킹 없음.
- 미정: Q1 오개념 M1~M5 추론(게임엔 M1~M4 반영, M5 보류), Q3 교과서 출판사·쪽, Q4 NPC 외형 수위(1차 시안 1-플랫-교실.png 로 1차 판단 통과 — 특성이 보이되 희화화 없음).

## Brand Commitments

- 제목 「모두의 교실 디자인 스튜디오」. 과정 5단계 이름은 교과서 그대로: 문제점 찾기·조사하기·설계하기·테스트·수정·돌아보기.
- 모든 이미지 요소(교실·NPC·부품·카드 그림·UI 패널·버튼·아이콘·배지)는 GPT-6.1-sol 생성 PNG. SVG·CSS 로 그린 평면 UI 금지(사용자 규칙 2026-10-10). 그림에 글자를 넣지 않는다.
- 1차 게이트(2026-10-10) 확정 컨셉: **1 카툰 플랫 미니멀**(`tokens.json themes.flat-studio`). world-trade 는 생산 방식(전부 Sol)만 참고, 그림체·UI 는 따르지 않는다.

## Product Principles

- 이 게임 자체가 유니버설 디자인이어야 한다. 주제와 제품이 어긋나면 안 된다.
- 한 화면에 결정 하나. 안내문·힌트·부제 없음.
- 반응은 사용자(NPC)가 말한다. 시스템이 옳고 그름을 선언하지 않는다.
- 색만으로 정보를 나누지 않는다. 글자·아이콘·모양이 항상 같이 간다.

## Accessibility & Inclusion

전 조작 키보드 가능(Tab/Enter/화살표), 보이는 포커스 링, 본문 20px 이상 + 글자 크기 2단(×1.25), 글자 대비 4.5:1 이상(고대비 테마 7:1), 모든 NPC·부품·카드에 텍스트 라벨, `prefers-reduced-motion` 존중, 효과음 비의존. NPC 특성 묘사는 존엄하게, 같은 비례·같은 표정 어휘.
